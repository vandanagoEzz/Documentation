# goEasy Documentation

Internal documentation for goEasy. This repository is private.

## Contents

### Access checklist: new hires and departures
[docs/access-onboarding-offboarding.md](docs/access-onboarding-offboarding.md)

A simple checklist for giving a new employee or contractor the access their role needs, and for removing all of it when they leave. It has a table of what each role gets, nine onboarding steps, and eleven offboarding steps in the order to revoke access (highest risk first). It also covers the access log and quarterly review. Owner: Vandana Mishra.

### Operations Manager: responsibilities and accountability
[docs/operations-manager-responsibilities.md](docs/operations-manager-responsibilities.md)

What the Operations Manager is responsible for and measured on. It covers the primary outcome (enough vetted drivers to meet demand), lead and lag measures, 90-day goals, daily, weekly and monthly responsibilities, what the role decides alone and what goes to the founder, and standards of behavior. It ends with open points to confirm, such as lag-measure targets.

### Driver matching: current system (PDF)
[docs/goEasy_Driver_Matching_Current_System.pdf](docs/goEasy_Driver_Matching_Current_System.pdf)

How driver matching works today, based on the latest code and Jira ticket UAD-1024. It explains when matching runs, how drivers are filtered and selected, how drivers are scored (rider history, route history, distance, completed rides, recent activity and penalties), the live settings, the status of the September problems, and what is still open. Updated October 25, 2026. Check that the code is deployed before treating the rules as live.
